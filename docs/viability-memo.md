# Viability memo — a small experiment for a hands-on senior PM

## Why this slice

The [public Senior Product Manager role](https://jobs.ashbyhq.com/everai/67415245-9710-4d32-a544-735d779e1d44) emphasises owning an opportunity, building a small meaningful experiment, measuring its outcome and deciding what comes next. This concept demonstrates that loop at a reviewable scale.

| Work demonstrated | Evidence in this project |
|---|---|
| Problem framing | Public context, third-party signal and inference are labelled separately. |
| A bounded intervention | Three light questions and a message-eight memory review. |
| Hands-on delivery | A working static conversation, memory controls and local event log. |
| Measurement discipline | Day-seven return is primary; secondary metrics and guardrails have explicit definitions. |
| Quality ownership | Repeatable logic checks, real-page browser checks and recorded results. |
| Decision making | Synthetic outcomes are illustrative; the decision is a limited real test, not an invented win. |

## Customer value hypothesis

Correct recall could reduce repetition. Visible correction and Forget could preserve agency. If those effects make a user more comfortable returning, the intervention may create lasting value. This has not been established through research or live data.

## Feasibility

The prototype is deliberately static and isolated. A production test would need consented assignment, durable return measurement, reliable correction and deletion semantics, and an existing product integration. It should reuse established production capabilities rather than build a separate platform.

## Commercial viability

The value case depends on incremental return, not interaction with a novelty. Estimate cost per retained user only after measuring a real lift and delivery cost. We have no pricing, revenue, traffic or operating-cost evidence for this proposal.

## Risk and next decision

The main risks are premature familiarity, incorrect recall, confusing Forget with transcript deletion, and attributing return gains to a bundle of UI changes. Start with comprehension research, then a small pilot with agreed stop rules. A signal of discomfort is grounds to revise even if engagement rises.

## Evidence limits

The [third-party review](https://shouldieventry.com/products/candy-ai-review/) is not internal validation. This project is independent and synthetic. It does not demonstrate production delivery at company scale or a real retention improvement, and it is not an assessment of every requirement in the role.
